
# MailManager 安全漏洞修复计划

## 目标
修复 P0/P1 安全漏洞，减少冗余设计，确保程序功能正常。

## 核心策略
**将凭据管理从前端迁移到后端**，前端不再持有敏感信息。

---

## 修改清单

### 第1步：Git 新建分支
```bash
git checkout -b fix/security-audit
```

### 第2步：后端修改 (`src-tauri/`)

**2.1 添加依赖** (`Cargo.toml`)
- 添加 `tauri-plugin-stronghold` 用于加密存储凭据

**2.2 新增 stronghold 模块** (`src-tauri/src/store.rs`)
- 初始化 Stronghold 加密存储
- 提供 `save_credentials(account_id, credentials)` / `load_credentials(account_id)` / `delete_credentials(account_id)` / `list_account_ids()` 函数
- 凭据结构：`{ email, client_id, refresh_token }`（移除 password）

**2.3 修改 `mail.rs`**
- `MailAccount` 结构体：移除 `_password` 字段
- `MailboxResult` 结构体：移除 `refresh_token` 字段
- 新增 `import_accounts(raw_text)` 命令：解析账号文本，将凭据存入 stronghold，返回 `[{id, email}]`
- 新增 `delete_account(account_id)` 命令：从 stronghold 删除凭据
- 修改 `fetch_mailbox`：通过 account_id 从 stronghold 加载凭据，内部完成 token 刷新并更新 stronghold，不返回 refresh_token

**2.4 修改 `lib.rs`**
- 注册 stronghold 插件
- 注册新命令：`import_accounts`、`delete_account`

### 第3步：前端修改 (`src/`)

**3.1 修改 `mail.ts`**
- `MailAccount` 类型简化为：`{ id: string, email: string }`
- 移除 `parseAccountLine`、`createAccountId` 等不再需要的函数
- 移除 `raw_line` 相关逻辑
- `fetchMailbox` 改为：`invoke("fetch_mailbox", { account_id, protocol, folder, limit, offset })`
- `fetchAccount` 移除 token 刷新逻辑（后端内部处理）
- 新增 `importAccounts(raw_text)` 函数：调用后端 `import_accounts` 命令
- 新增 `deleteAccount(account_id)` 函数：调用后端 `delete_account` 命令

**3.2 修改 `App.tsx`**
- accounts 状态改为 `MailAccount[]`（仅 id + email）
- localStorage 仅存储 `[{id, email}]`，不含任何敏感信息
- 移除 ImportDialog 中的密码/凭据处理逻辑，改为调用后端 import
- 移除 token 刷新后的 accounts 更新逻辑
- 修改 deleteAccount 调用后端删除
- iframe sandbox 移除 `allow-popups-to-escape-sandbox`

### 第4步：验证
- `cargo build` 确认 Rust 编译通过
- `pnpm build` 确认前端构建通过
- 功能测试：导入账号、取件、删除账号流程正常

## 数据流变化

**修复前：**
```
导入文本 → 前端解析 → localStorage(明文全量) → IPC传全量凭据 → 后端处理 → 返回refresh_token → 前端更新localStorage
```

**修复后：**
```
导入文本 → IPC传原始文本 → 后端解析+加密存储 → 返回[{id,email}] → 前端存储(仅id+email)
取件：前端传account_id → 后端从加密存储加载凭据 → 处理+内部刷新token → 返回邮件(不含token)
```

## 移除的冗余设计
1. `raw_line` 字段 — 永久移除
2. `password` 字段 — OAuth 不需要，永久移除
3. 前端 `parseAccountLine` / `createAccountId` — 迁移到后端
4. 前端 token 刷新逻辑 — 迁移到后端
5. `MailboxResult.refresh_token` — 不再返回前端
